# Game Phases

Two phases:

```rust
pub enum GamePhase {
    Lobby,
    InProgress,
}
```

## Lobby

- Players connect, set names, pick consoles.
- Captain (player at `CaptainChair`) sees an **Engage** button. No one else does.
- `HelmInput`, `ToggleRedAlert`, and `SetView` are silently ignored by the server.
- `available_consoles()` reflects free seats.

## Transition: `StartGame`

Server-side guards (in `lobby_handler.rs`):

1. Phase is `Lobby`.
2. `sender_token == captain_token()`.

If both pass:

1. World is generated by `asteroid_spawner` (deterministic, seeded).
2. Ship and asteroid Bevy entities spawn into the Rapier world.
3. Phase flips to `InProgress`.
4. `WorldSetup { world }` then `GameStarted` broadcast to all.

## In-Progress

- Helm sends `HelmInput` at 10 Hz.
- Captain toggles Red Alert and changes View Mode.
- Simulation runs every frame; `SimState { snapshot }` broadcasts at 10 Hz.
- Late joiners get a `Welcome` with `state.world = Some(WorldData)` so they see the same field.
- Players who disconnect free their console immediately. Reconnection with the same token auto-restores it if free.

## What's *not* a phase yet

Game-over, paused, between-rounds — all out of scope today. PRD #66 explicitly leaves "ship destruction / game-over state" out of scope.
