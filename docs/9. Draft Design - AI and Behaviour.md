# AI & Behaviour

## Overview

Enemy ships (and other mobile entities) use a state machine with predefined states and condition-based transitions. The state machine is defined in the entity config TOML and can be overridden per-spawn in scenario files.

## Predefined States

| State | Behaviour |
|---|---|
| `idle` | Stationary, does nothing. |
| `patrolling` | Moves between a list of waypoints (anchor names or absolute positions), loops. |
| `pursuing` | Moves toward a target entity at maximum speed. |
| `attacking` | Within weapons range of target — fires phasers and/or torpedoes. |
| `fleeing` | Moves away from a threat at maximum speed. |
| `warping_out` | Graceful exit: accelerates and despawns. Used when a scenario unloads and the entity has a graceful exit behaviour. |

## State Machine Definition

Defined in the entity config TOML:

```toml
[behaviour]
initial_state = "patrolling"

[[behaviour.state]]
name = "patrolling"
waypoints = ["patrol_start", "patrol_mid", "patrol_end"]

[[behaviour.transition]]
from = "patrolling"
condition = "on_attacked"
to = "pursuing"

[[behaviour.transition]]
from = "pursuing"
condition = "in_weapons_range"
to = "attacking"

[[behaviour.transition]]
from = "attacking"
condition = "hull_below"
threshold = 0.3
to = "fleeing"

[[behaviour.transition]]
from = "fleeing"
condition = "on_scenario_unloaded"
to = "warping_out"
```

## Transition Conditions

Transition conditions reuse the same vocabulary as scenario trigger conditions where applicable, plus additional in-simulation conditions:

| Condition | Description |
|---|---|
| `on_attacked` | Entity takes first hit (fires once) |
| `on_destroyed` | Entity hull reaches 0 |
| `on_scenario_unloaded` | Owning scenario unloads |
| `on_timer` | N seconds elapsed in current state |
| `in_weapons_range` | Target is within weapons range |
| `hull_below` | Hull integrity below a threshold (0.0–1.0) |
| `target_destroyed` | Current target has been destroyed |

## Graceful Exit

- Entities in state `warping_out` are orphaned when their owning scenario unloads — they self-manage their despawn.
- The scenario unloads immediately; it does not wait for graceful exits to complete.

## Spawn Overrides

A scenario can override any behaviour parameter per-spawn using a flat override block:

```toml
[[spawn]]
entity = "entities/enemy_patrol.toml"
position = "patrol_start"

[spawn.overrides]
behaviour.initial_state = "idle"
on_attacked.scenario = "scenarios/ambush.toml"
```
