# Space Stations

Space stations are persistent world entities placed by the default scenario (or other scenarios) at named map anchors or absolute positions.

## Entity Config

Stations are defined as TOML entity files with the following properties:

- `tags` - must include `"station"`. Add `"comms_contact"` if the station can be hailed.
- `radius` - collision/visual size
- `hull_integrity` - hit points
- Visual representation: geometric shape (e.g. cylinder or torus) on the viewscreen.
- Visible on Science long-range radar and Weapons radar (if their tag filters include `"station"`).

## Triggers

Stations can define triggers in their entity config (see Scenario File doc for trigger syntax). Common triggers:

- `on_attacked` — fires once on first hit (e.g. sends a distress call scenario)
- `on_destroyed` — fires when hull reaches 0 (e.g. triggers a follow-on scenario)

These can be overridden per-spawn in the scenario file using flat override blocks.

## Scenario Integration

- Stations are spawned by scenarios (typically the default scenario for fixed world furniture).
- A station spawned by a scenario is owned by that scenario.
- If the owning scenario unloads, stations without a graceful exit behaviour are despawned immediately.
- Stations can be configured with a graceful exit — e.g. they do nothing (are static), so they would typically hard-despawn unless the default scenario (which never unloads) owns them.

## Comms

- Stations tagged `"comms_contact"` appear in the Comms console contact list.
- Incoming messages from stations (triggered by scenario events) appear on the Comms console.
- The crew can select predefined responses, which may trigger further scenario events.
