# Scenario File

Scenarios are TOML files that layer dynamic content over the map. They are not selected at startup — they are loaded on the fly during gameplay, triggered by other scenarios or entities.

## Loading

- The default map hardcodes a `default_scenario` path, which is always loaded on top of the map at startup.
- The default scenario is never unloaded. It contains fixed world furniture: space stations, patrolling ships, etc.
- Additional scenarios are layered on during play. Each scenario owns the entities it spawns.
- When a scenario unloads, it despawns all owned entities immediately. Entities with a graceful exit behaviour (`warping_out`, etc.) are orphaned and self-manage their despawn.

## Parameterisation

Scenarios can receive named entity ID parameters from the trigger that loaded them. Parameters are referenced in the scenario TOML as `$param_name`.

Example: a distress call scenario receives `$station` and `$attacker` as entity IDs from the trigger that fired when the station was attacked.

## Preloading

A scenario can declare entity files to preload before it begins spawning:

```toml
preload = [
    "entities/enemy_ship.toml",
    "entities/rescue_shuttle.toml"
]
```

## Spawning Entities

```toml
[[spawn]]
entity = "entities/enemy_ship.toml"
position = "patrol_start"          # named map anchor
# position = [1000.0, 0.0, -500.0]  # absolute
# position = { entity = "$station", offset = [100.0, 0.0, 0.0] }  # entity-relative

# Optional: flat override of entity config values
[spawn.overrides]
on_destroyed.scenario = "scenarios/act2_aftermath.toml"
```

## Triggers

Triggers are declared in entity config files and can be overridden per-spawn. Scenarios can also define their own triggers.

### Condition Types

| Condition | Fires When | Named Params |
|---|---|---|
| `on_destroyed` | Entity hull reaches 0 | `self`, `attacker` |
| `on_attacked` | Entity takes first hit (fires once only) | `self`, `attacker` |
| `on_entered_region` | Ship enters a region entity | `self` (the ship) |
| `on_scenario_unloaded` | This scenario unloads | — |
| `on_timer` | N seconds after this scenario loads | — |

### Trigger Actions

A trigger can perform one or more actions:

```toml
[[trigger]]
condition = "on_destroyed"
entity = "$station"
actions = [
    { load_scenario = "scenarios/distress_call.toml", params = { station = "$station", attacker = "$attacker" } },
    { remove_objective = "protect_station" },
    { add_objective = { id = "failed_protection", text = "The station has been destroyed.", optional = false } }
]
```

```toml
[[trigger]]
condition = "on_timer"
seconds = 30.0
actions = [
    { load_scenario = "scenarios/reinforcements.toml" }
]
```

## Objectives

Scenarios can add and remove objectives, which appear on the Comms console.

```toml
[[objective]]
id = "rescue_crew"
text = "Rescue the survivors from the damaged station."
optional = false
```

- Objectives have a status: `active`, `completed`, or `failed`.
- Completed/failed objectives remain visible until the Comms operator clears them.
- Objectives are ordered: mandatory first, optional below.
- Trigger actions can add, complete, or fail objectives by ID.

## Comms Scripts

Scenarios can define incoming messages from entities that appear on the Comms console:

```toml
[[comms]]
from = "$station"
message = "Mayday! We are under attack! Please respond!"
trigger = { condition = "on_attacked", entity = "$station" }

[[comms.responses]]
text = "We're on our way."
actions = [{ load_scenario = "scenarios/rescue_mission.toml", params = { station = "$station" } }]

[[comms.responses]]
text = "We cannot assist at this time."
actions = []
```
