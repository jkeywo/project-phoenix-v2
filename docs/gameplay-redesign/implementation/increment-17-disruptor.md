# Increment 17 — Bounded physical disruption through shared EMP

## Adopted first S021 consumer

Root approved a Comms-hosted actual generic weapon using the existing EMP
payload, physical impact and component condition owners. This is one bounded
disruption objective, not completion of every possible information/access
operation. No hacking controller, network intrusion, enemy ControlSystem
command, ownership change, hidden interior reading or new job manager is added.

An optional reference Cruiser retains its six claimable seats and base hardware.
Add one actual finite bolt bank with a supported authored EMP duration, actual
mount/arc/range/projectile/impact, local energy consumer, power allocation,
compartment placement and ordinary damage bindings. Reuse the existing portable
weapon/payload/condition machinery and existing per-bank AI. The effect is not
free electronic exposure: the real projectile must hit through the existing
shield/material/deck/compartment path and produce an eligible deposit. Physical
collateral remains possible under ordinary impact rules.

The bank belongs to its own actual Console hosted at Comms, with the existing
home/visiting/delegation and Console rating contracts. This adds a tab rather
than a claimable seat or role-name rule. Its supported feeds explicitly permit
the existing TacticalRadar and shared combat-lock publication; co-hosting does
not pool knowledge. Human targeting uses the bank's independently admitted
target/hold assignment, and firing/stop/charge use the existing bolt controls.
The ordinary individual bank AI uses only that same permitted current evidence
and its actual admitted authority. There is no second global electronic planner.

Start with the existing reusable Tactical screen/components and Console hosting.
Verify actual projected bank ownership, eligible contacts, selected per-bank
target and normal semantic action/command routing. Existing beam controls use a
ship-wide mode owner, so merely moving a beam to Comms would not establish
independent manual reachability; the initial bolt uses the existing independent
bank action path. If the shared screen shows unrelated controls, withhold or
hide them through its existing capability projection rather than granting Comms
the other weapons or creating a separate combat implementation.

## Effects, counterplay and evidence

The existing finite EMP receipt, automatic expiry and resistance accumulation
remain authoritative. Shields, physical obstruction, range/arc, target evidence,
equipment conditions, reserve/heat and existing EMP receiver policy provide
counterplay. SignalProtection only suppresses its declared electronic
interference effects; it is not silently extended into physical EMP immunity.
Shared own System status shows actual EMP separately from destruction. The
attacker receives ordinary impact/effect reports permitted by existing evidence,
never a private enemy component census or guaranteed remote disablement result.

Workshop uses the actual shared weapon, energy, ownership/Console and interior
editors, accepted source/history/includes and Preview/Test validation. No new
effect schema or duplicate EMP processor is justified by this configuration.

Required evidence includes the accepted optional recipe preserving base seats,
systems, ratings and resource rules; real client builder/component/semantic
action reachability at the hosted Comms Console; Human bank selection/fire/stop
and ordinary AI operation through existing admission; positive paid physical
EMP and failed shield/geometry/unfunded cases; original condition/resistance
expiry and restored operation without a repair ritual. Continue actual finite
work/EMP through fresh JSON for at least 360 complete captures/digests, with
malformed ownership/payload/condition candidates refusing before writes.

Runtime, authoring and full-host source proof are separate from native execution,
device/browser journeys, balance/performance and crew workload acceptance.
Broader selected information/access operations remain open where they need a
separate supported objective and delivery/prerequisite policy. This example does
not invent those policies or close all of increment 17.
