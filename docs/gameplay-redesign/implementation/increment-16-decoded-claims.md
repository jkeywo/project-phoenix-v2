# Increment 16 — Read-only decoded typed claims

## Adopted bounded projection contract

Root approved this projection before runtime; independent Personnel review
confirmed that no physical reception receipt or personnel identity is disclosed.

This completes the already adopted promise to show original supported typed
content after actual paid decoding. It adds no capture events, equipment,
controller, payment, work frontier or new source of authority. The existing
private immutable captured payload remains the sole source, with the existing
capture clock, emission clock, decoded clock and attributed literal sender name.

`DecodedCommsEvidence` gains a closed read-only claim value distinct from
`CommsRadioContent`, `GenericCommsRequest`, `CommsRequestReference` and ordinary
addressed inbox progress. It is derived only when the same row has completed
decode; headers and ordinary AI feasibility still cannot see its contents early.
No new retained claim copy or correlation index is created.

The initial supported projection exposes:

- Text as the existing literal body, without additional metadata.
- Report Status as its request kind.
- Form Up as its request kind and original finite integer World-x/z slot.
- Media Call as its request kind and requested Audio/AudioVideo mode. This is
  text metadata; it supplies no media bytes, device access or call eligibility.
- Outcome as its supported request claim, original request emission/heard/read
  clocks, actual transmitted decision/decision clock, and a transmitted status
  availability/observation-clock claim where present. It never reveals the
  report's private System identity. These are attributed foreign claims, not
  proof that this interceptor heard the original request or that work happened.

Do not publish source/recipient actor UUIDs, origin IDs, key IDs, audience,
formation sequence, private request-reference bindings, routes, System IDs or
craft IDs. A subsequently integrated Receive Craft kind may expose its kind
alone; its private craft identity must not be copied. Every new request kind
needs an explicit safe projection rather than serialising its machinery DTO.

An intercepted outcome remains useful even when the original request was never
captured: display the original transmitted claim and clocks without inventing
an interceptor-local association. Do not resolve a sender name or report into a
contact/alias, attach a dossier automatically or use private source mappings.

The current permitted Comms view and existing capture widget render these fields
as dated read-only content using the ordinary safe localisation/text path.
Selection still selects paid decoding only. No reply/accept/report/formation/call
or machinery action is attached to decoded content. No request consumer, planner
receipt observer or Comms response policy consumes this new projection.

## Continuation and evidence

Private canonical captured state and its paid frontier remain unchanged. The
public claim is recomputed from the immutable payload for live publication and
whole-candidate saved-publication consistency. Keep the existing missing-emitter
history rule; this projection adds neither actor retention nor an authentication
claim for erased history. Root coordinates affected public schema/epochs.

Required targeted evidence: no typed fields before decode; exact supported
request parameters and transmitted outcome facts after decode; malformed closed
GUI values refused; routing/private identities absent recursively; foreign claims
produce no addressed receipt, reply, Formation or media participation. Extend
the real actual-emission/paid-decode/fresh-JSON360 proof with a typed payload and
candidate public-claim contradiction refusal, preserving existing full-capture
and digest checks. Browser/Workshop/native acceptance remains separately recorded.

Dynamic key acquisition/revocation, opaque keyless forwarding, relay-hop or
retransmission interception, audio/video interception/recording and arbitrary
phantom contacts are not added by this contract. They require separately selected
real consumers and provenance rules.
