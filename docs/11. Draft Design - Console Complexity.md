# Console Complexity

## Overview

When selecting a console, players can select a complexity rating for that console. Low complexity consoles have their advanced functions either automated or abstracted to reduce cognitive load for new or overwhelmed players.

Players can change the complexity of their console at any time via a settings menu. The change takes effect immediately with no cooldown.

**Complexity is a console-level property**, not a player-level property. When a player joins a console, they inherit that console's current complexity setting. If the player's stored preference (in browser localStorage) differs from the console's current setting, the client automatically sends a `SetComplexity` message to sync the console to the player's preference.

## Console Coverage

**No complexity level (out of scope):**
* Captain's Chair
* Communication
* Helm

**Complexity available:**
* Tactical
* Science
* Engineering

## Shield Frequency System

The game features a shield frequency mechanic with 3 frequencies: alpha, beta, gamma. Enemy shields are set to one frequency. The Science console can detect the enemy shield frequency when targeting. The Tactical console can tune phasers to match the frequency for a full damage bonus. Torpedoes are unaffected by shield frequency.

## Low Complexity Console Details

### Tactical

**Simplifications:**
* **Damage bonus:** Instead of tuning phasers to match enemy shield frequency for a full bonus, Low Complexity Tactical applies a guaranteed flat damage bonus equal to the regular bonus divided by the number of frequencies (1/3 of full bonus). This trades peak damage for consistency.
* **Auto-fire torpedoes:** Automatically fires one torpedo when the target's shields reach 0 HP. Holds fire while shields are up.
* **Auto-fire defaults:** All auto-fire settings default to ON.

**Behavior when switching:**
* Low → Full: Immediately unlocks frequency tuning. Auto-fire settings persist (remain ON).
* Full → Low: Immediately loses frequency tuning, damage drops to 1/3 flat bonus.

### Science

**Simplifications:**
* **Frequency ignoring:** Ignores enemy shield frequency if **either** Science **or** Tactical console is set to Low Complexity. This is a cascading simplification: if either console cannot participate in the frequency mechanic, the entire frequency system is skipped to avoid confusion.

**Behavior when switching:**
* Low → Full: Immediately begins showing shield frequency info (provided Tactical is also Full Complexity).
* Full → Low: Immediately stops showing shield frequency info.

### Engineering

**Simplifications:**
* **Battery removal:** Removes the battery mechanism that allows assigning up to 2 additional power points (beyond the base 6).
* **Compensating bonuses:** The base 6 power points grant slightly higher bonuses to compensate for the loss of battery points.

**Power Allocation System:**
* 6 base power points can be assigned across consoles
* Full Complexity: Can assign up to 2 additional points using battery (8 total), but battery drains over time
* Low Complexity: Maximum 6 points, no battery
* Bonus array per console: [-50%, +0%, +25%, +50%] based on points assigned
* Consoles with only 1 point are protected from automatic point removal

**Behavior when switching:**
* Full → Low: Battery mechanism is immediately removed. If total power exceeds the new maximum (6), excess points are removed from consoles with 2+ points (protecting consoles with only 1 point).
* Low → Full: Battery mechanism returns, battery starts empty, 6 base points remain assigned.

## Complexity Persistence

* Complexity settings are stored per-console in the browser's localStorage
* On first use of a console, a pop-up prompts the player to select their preferred complexity
* When a player joins a console, if their stored preference differs from the console's current complexity, the client automatically sends a `SetComplexity` message to update the console
* Complexity changes are synchronized to the server via `SetComplexity` messages containing: console identifier, complexity level, and player token

## Server-Side Handling

* Server stores complexity on the console, not the player
* Server validates `SetComplexity` messages by checking:
  * Player token is valid and connected
  * Player is currently assigned to the specified console
  * Complexity value is valid (Low or Full)
* Server broadcasts complexity changes to all clients
* Concurrent complexity changes: last message wins

## Design Philosophy

* **Simplicity has a cost:** Low complexity modes intentionally reduce peak effectiveness in exchange for reduced cognitive load
* **Immediate changes:** Complexity changes take effect immediately with no cooldown or confirmation
* **No notifications:** Team members are not notified when a player changes complexity (the power difference is the signal)
* **Console-level settings:** Complexity is tied to consoles, not players, ensuring consistent behavior regardless of who is operating the console
