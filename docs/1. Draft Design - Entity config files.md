# Entity Config Files

## Format & Loading

- Config files are TOML format.
- Files are fetched at runtime via HTTP by JS (`fetch(path)`), then passed to Rust via `wasm_load_config(path, toml_str)`.
- The cache is keyed by file path string (e.g. `"entities/asteroid_small.toml"`).
- Loading is on-demand: Rust queues config requests as outbound events, JS drains them each frame, fetches, and calls `wasm_load_config` when ready.
- Scenario and map files can declare entity files to preload before gameplay begins (to avoid mid-game fetch latency for common entities).

## Entity Tags

Every entity declares a list of string tags. Tags are used by the radar system to filter what each console sees, and by other systems (region blocking, comms contacts, etc.).

Initial tag vocabulary:
- `star`
- `planet`
- `asteroid`
- `asteroid_field`
- `ship`
- `player` (combined with `ship` for the player ship)
- `enemy` (combined with `ship` for enemy ships)
- `station`
- `torpedo`
- `debris`
- `comms_contact`
- `region`

An entity can have multiple tags. Example: `tags = ["ship", "enemy"]`

New tags can be added in TOML without changing Rust code.

## Asteroid

- `tags` - list of tags (must include `"asteroid"`)
- `size_min` - minimum radius
- `size_max` - maximum radius
- `colours` - list of colours for the surface
- `hull_integrity` - hit points

## Ship

- `tags` - list of tags (must include `"ship"`)
- `radius` - capsule radius
- `length` - capsule length
- `max_speed_forward` - maximum forward speed
- `max_speed_reverse` - maximum reverse speed
- `acceleration` - acceleration rate
- `deceleration` - deceleration rate
- `turn_speed` - maximum yaw rate
- `hull_integrity` - total hit points
- `repair_rate` - hull HP restored per second when repairing
- `repair_cooldown` - seconds between repair cycles
- `phaser_damage` - damage per phaser hit
- `phaser_colour` - colour of phaser beam
- `phaser_cooldown` - seconds between phaser shots
- `phaser_auto_arc_reduction` - degrees subtracted from arc when deciding to auto-fire (default 30)
- `torpedo_count` - total torpedo supply
- `torpedo_damage` - damage per torpedo hit
- `torpedo_speed` - torpedo travel speed
- `torpedo_turn_rate` - maximum torpedo turn rate (limited, configurable)
- `torpedo_lifespan` - seconds before torpedo expires
- `torpedo_load_time` - seconds to load one torpedo tube
- `impulse_speed_multiplier` - speed multiplier when impulse is active (e.g. 10.0)
- `impulse_charge_time` - seconds required to charge impulse drive

### Per-Console Radar Config

Each console has its own radar range and tag filter, defined within the ship config:

```toml
[helm.radar]
range = 500.0
shows = ["asteroid", "ship", "torpedo", "station", "debris"]

[weapons.radar]
range = 800.0
shows = ["ship", "station", "torpedo"]

[science.radar]
range = 5000.0
shows = ["ship", "station", "asteroid_field", "region"]

[science.system_chart]
range = 50000.0
shows = ["star", "planet", "asteroid_field"]
```

### Power Multiplier Tables

Power multipliers are defined as lookup tables per console (1–4 power points, 2 = normal):

```toml
[helm.power_multipliers]
1 = 0.6
2 = 1.0
3 = 1.3
4 = 1.5

[weapons.power_multipliers]
1 = 0.6
2 = 1.0
3 = 1.3
4 = 1.5

[science.power_multipliers]
1 = 0.6
2 = 1.0
3 = 1.3
4 = 1.5
```

### Shield Config

```toml
[shields]
hp_per_facing = 20
regen_per_second = 0.33
offline_duration = 10.0
```

### Battery Config (see Engineering Console doc)

```toml
[battery]
# Rate table indexed by total allocated power points (3–8)
# Positive = recharge, negative = discharge (units per second)
rates = [6, 5, 4, 2, -2, -6]
capacity = 100.0
emergency_threshold = 25.0  # % charge required before Engineering regains control
```

## AI Behaviour (see AI & Behaviour doc)

Ship entity configs declare a default state machine with states and transitions. These can be overridden per-spawn in scenario files.
