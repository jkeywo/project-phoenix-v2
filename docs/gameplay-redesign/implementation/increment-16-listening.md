# Increment 16 — Finite listening and ordinary public chatter

**Adopted contract, 16 October 2026; no runtime or acceptance claim.**
This prepares the next bounded S066 consumer after the reviewed S021 source
packet. It does not change networking, create message capacity, expand crypto
acquisition, or claim a complete increment 16 exit.

## Intended player activity

Comms chooses which supported channels deserve the available listening coverage.
Routine public traffic supplies things worth noticing without a scenario script
having to manufacture every transmission. A player can keep a private operational
channel covered, or spend coverage looking for public information. Missing a
live transmission is possible; changing priorities later cannot retrieve it.
Human and ordinary AI use the same authored equipment and command boundary.

The first consumer is simultaneous channel selection, not a frequency puzzle,
rotating minigame, message quota or queue to clear. It complements existing paid
capture/decoding: reception must occur before there is anything to decode.

## Equipment, intent and information

An optional closed listening profile on the actual Radio specifies a positive
number of simultaneous monitored channels and an initial priority order. The
order is an exact permutation of that equipment's configured channel IDs; the
coverage is no greater than their count. The first available slots in the current
order are monitored simultaneously. No hidden receiver, signal count or private
traffic activity influences the selection.

Absent this optional profile, existing radios continue covering all their
configured channels. Do not reinterpret shipped data or change existing power
tuning merely to introduce this mechanism. A later optional reference fit can
offer more channels than slots to demonstrate a real choice.

The actual Comms System owns one current priority order. A normal admitted
`SetCommsListeningOrder` replaces that complete order after validating actual
System authority, current equipment and exact membership. It does not issue a
machinery action to another System. The permitted own Comms view publishes
configured choices, current priorities, supported slot count and currently
monitored channels. It exposes neither hidden traffic nor held-key identities.
Other Console feeds remain explicit; co-hosting grants nothing.

Selected priorities remain intent when the equipment is unpowered, damaged,
delegated or temporarily unavailable. Current monitored capability is derived
from the real paid Radio sample. The existing per-System controller can set the
same order under normal admission; Human ownership stands it down. No special
temporary-filling controller or extra AI scheduler is introduced.
Default ordinary AI retains the current authored/operator priorities through
handoff. A reusable authored policy can explicitly choose a justified supported
change; starting Backfill alone never resets the crew's order.

## Actual reception boundary

Extend the existing same-interval Radio endpoint measurement with the monitored
channel selection. Retain its actual availability, Operation factor and single
paid continuous work call. The new choice creates no per-message cost, listening
token, traffic backlog or resource account. Existing discrete emission work
remains unchanged. Source transmission is allowed on any of its supported
channels; transmitting does not secretly replace the chosen receive order.

Apply the chosen receive gate wherever that actual endpoint needs to hear the
channel: addressed text/requests, returned outcomes, actual original-event capture
and each receiving relay hop. A media carrier also requires that both endpoints
currently cover its selected call channel; existing call intent/consent never
overrides physical eligibility. Preserve the same deterministic direct-first
route search, keys, range, field/terrain and protection checks. Do not turn a
relay into an unobserved capture producer or alter Phoenix transport classes.

An ordinary one-shot transmission missed during an uncovered interval is lost to
that receiver. Existing explicitly sustained requests/outcomes can arrive only
when their real paid service later has a viable monitored route; their original
identity and event clocks remain unchanged. No new retry queue, retrospective
archive scan, synthetic receipt or free retransmission is added. Already received
evidence and accepted onboard work survive a later coverage change.

## First contextual public chatter consumer

The smallest useful first context is the ship's selected alert condition. Use
the existing own `Captain` typed publication's `red_alert` value through an
explicit configured Comms Console feed. That publication name is not a seat rule:
it neither moves Alert controls nor grants a Captain map. The optional reference
fit adds the exact supported feed rather than giving every Comms System access.
Require one unambiguous permitted publication; absent, conflicting or stale
context withholds this producer. Never read the underlying private machinery
flag directly as an alternative to that view.

The current typed alert publication lacks an original producer clock. Extend
that same publication with ordinary dated `ObservationMetadata` for its alert
sample, bound to its actual own Alert System. Do not manufacture freshness from
unchanged bytes, global time, a co-hosted tab or the date when Comms inspected it.
The supported latest sample is dated at the current fixed tick or the immediately
preceding normal publication boundary, never in the future. Missing metadata is
unknown for this opted-in consumer. The existing authoritative alert remains the
only machinery truth; this adds dated observation metadata, not a second flag,
state store or freshness timer. Snapshot preflight validates the dated alert
sample against the accepted source and ordinary publication frontier.

An optional accepted public-traffic profile specifies that explicit alert feed,
one public unkeyed channel, two bounded text templates and positive minimum
successful-emission spacing. The two closed semantic states are **red alert
selected** and **routine alert selected**. Text describes current reported own
intent: for example, "We have selected red alert" or "We have selected routine
alert." It does not claim that an enemy exists, combat ended, weapons fired,
machinery obeyed, damage was repaired or other work completed. No arbitrary
template expressions, target lookup, coordinates or private actor substitutions
are supported. Richer contextual target/status exchanges require their own
explicit permitted input and real consumer.

The existing single ordinary Comms tree can choose a supported public-context
verb below real reading, decisions and released planned requests. The same
admitted Radio send path revalidates the current permitted dated context,
semantic choice, successful-report frontier and actual equipment, pays existing
discrete channel work and emits one normal `All` text transmission. Callers
cannot supply invented context or bypass this check by choosing a template.
Human free text remains unchanged; Human ownership stands this ordinary
controller down. No AI voice, audio synthesis, fabricated speaker or direct inbox
injection is used.

Retain only the latest successfully reported semantic state and actual
successful emission tick in the actual Comms owner's canonical
continuation state, alongside the listening intent. The first genuinely known
state can introduce the ship's posture once; thereafter the producer is eligible
only when the currently observed semantic state differs from its last successful
report and minimum spacing has elapsed. Unchanged intent never repeats merely
because time passed. Read the latest actual permitted state again when eligible:
several unsent changes coalesce, without a pending text queue or intermediate
catch-up reports. If it returned to the last reported state, there is nothing
new to announce.

Attempting or displaying a line consumes no semantic frontier or cooldown;
actual successful paid emission advances them together. Power loss, Human
takeover or unavailable context creates no burst after recovery. Dismissing an
inbox copy cannot reset this frontier. Spacing paces this optional producer, not
the number of messages humans or other Systems may send. There is no second
transmission history, timer manager or world event generator.

Ordinary recipients hear this genuine one-shot public intent claim only through
their current paid coverage and path. Capture obeys existing acquisition and
disclosure, so a missed announcement is not later recoverable through decoding.
